> **이 문서의 목적**
> 제1호가 잘 나온 이유를 규칙으로 고정한다. 두 번째부터 무너지는 것을 막는다.
> 취향이 아니라 **측정 가능한 규칙**으로 쓴다.

## 0. 대원칙 3줄

1. **INSIGHT는 미디어가 아니라 영업 자산이다.** 읽는 사람은 독자가 아니라 **발주 검토 중인 담당자**다.
2. **숫자는 적게, 구조는 많이.** 제1호는 외부 수치 2개뿐이고 나머지는 전부 판단 기준이다. 이게 강한 이유다.
3. **읽고 나서 "우리 회사는 어느 쪽인가"를 자문하게 만든다.** 그 자문이 문의로 이어진다.
4. **읽는 사람은 실패한 사람이 아니다.** 이미 대행사와 돌리고 있고, 숫자도 나오고 있다. 다만 손에 잡히는 게 없다. INSIGHT의 일은 가르치는 것이 아니라 **그 찜찜함에 이름을 붙여주는 것**이다.
5. **길면 안 읽힌다.** 정보를 다 넣으려다 공감을 잃는다. 하나만 남기고 나머지는 버린다.

> **v2.0 변경 (2026-08-27)**
> 분류별로 분량·형식을 나눴다. guide 는 검색·AI 인용 착지점이라 종전 분량을 유지하고,
> korea·taiwan 은 공감형으로 대폭 단축한다. 근거는 台湾 제2호 실측(838자)이다.

⚠ (3)은 외부 툴이 못 쓴다. 자사 관찰이므로 반드시 직접 채운다.
⚠ 결론을 다 주지 마라. 열어두면 문의가 들어온다.

## 3. ★ 비교표 — 이 기사 형식의 심장

제1호가 통한 이유는 이 표 하나다.

```
項目      判断できない書き方          判断できる書き方
アクセス   自然に囲まれた静かな場所     福岡空港からレンタカーで約1時間20分
交通手段   少し不便ですが価値あり       最寄り駅から予約制の送迎あり
客室      家族連れにもおすすめ         和室は最大4名まで同室可
```

### 표 설계 규칙

| 규칙 | 이유 |
|---|---|
| **3열 고정** — 항목 / 나쁜 예 / 좋은 예 | 4열이 되면 스마트폰에서 읽히지 않는다 |
| **5〜6행** | 3행은 근거가 약하고 8행은 안 읽는다 |
| 「나쁜 예」에 **실제로 흔한 표현**을 쓴다 | 독자가 자기 사이트를 떠올려야 한다 |
| 「좋은 예」는 **구체적 숫자·조건** | 형용사로 고치면 표의 의미가 없다 |
| 클라이언트 실명·특정 가능한 사례 금지 | 가공의 예로 쓴다 |

**표가 안 만들어지는 주제는 이 형식으로 쓰지 마라.** 다른 형식(케이스 해설·데이터 리포트)을 쓰거나, 주제를 바꾼다.

## 4. 체크리스트 — 독자를 판정대에 세운다 (guide 전용)

```
以下のうち二つ以上に当てはまる場合は、〜を確認することをおすすめします。
  · 항목 8개
```

| 규칙 | |
|---|---|
| 항목 수 | **7〜9개** |
| 임계값 | **「二つ以上」** 로 명시. 「一つでも」는 협박조가 된다 |
| 각 항목 | **1행.** 사실 서술로. 「〜すべき」 금지 |
| 마무리 | 「重要なのは、○○ではありません。△△です。」 로 프레임 전환 |

⚠ v2.0 korea·taiwan 에는 넣지 않는다. 짧은 기사에 체크리스트가 들어가면 정보량이 늘어 공감이 흐려진다. 판정은 인용박스가 대신한다.

체크리스트는 **영업 트리거**다. 여기서 2개 이상 걸리는 사람이 문의한다.

## 5. 🔴 팩트 규율 — 위반 시 발행 중단

### 5-1. 수치는 반드시 3점 세트

```
2026年7月、日本を訪れた韓国人は89万4,700人で、前年同月比31.9%増。
（日本政府観光局 JNTO 訪日外客数 2026年7月推計値、2026-08-19 発表）
 └ 기관명 ── └ 자료명 ─────── └ 기준연월 ─ └ 발표일
```

| 필수 | |
|---|---|
| 기관·자료명 | 「JNTO」만으로는 부족. 자료명까지 |
| 기준연월 | 언제 시점의 수치인가 |
| 발표일 또는 조사시점 | 추계치인지 확정치인지 구분되게 |
| 표본수 | 설문·조사라면 `N=1,000` 형태로 |

### 5-2. 금지

- ❌ **출처 없는 수치 1개도 금지.** 「約〜」「〜程度」로 뭉개는 것도 금지
- ❌ **자사 실적 수치를 웹에 쓸 때는 별도 승인.** 소개서에 실려 있어도 웹 공개는 다른 결정이다
- ❌ **클라이언트명 무단 노출.** 익명 처리가 원칙(明治·スキンケアブランド 선례)
- ❌ **추정을 단정으로.** 추정이면 「〜と考えられます」 또는 명시적 「推定」

### 5-3. 발표일은 확인한 단위까지만 쓴다 (v2.0)

원문에 「July 2025」까지만 있으면 **2025年7月発表** 로 쓴다. 다른 데서 본 것 같다는 이유로 일(日)을 붙이지 않는다. 과잉 정밀도는 팩트 집착형 독자가 가장 먼저 무는 곳이다.

### 5-4. 신판 확인 (v2.0)

연차 조사를 인용할 때는 후속판이 있는지 기관 사이트의 최신 발표를 끝까지 본다. 발표일이 6개월을 넘으면 반드시 확인한다.

> 실제 사고: 2026-08-27 리서치에서 資策會 MIC 影音調查의 2025-04 발표판을 인용했으나, 7일 전에 신판이 나와 있었다. 외부 리서치 툴 2개 모두 놓쳤다.

### 5-5. 발행 전 팩트체크

수치가 1개라도 들어가면 **`factcheck-gate` 스킬을 돌린다.** 검증 실패한 수치는 삭제하고 삭제 목록을 별도 보고. 검증 끝나기 전엔 번역·발행으로 넘어가지 않는다.

## 7. 문체 — 일본어 규율

### 7-1. 문말

| | |
|---|---|
| 기본 | **です・ます** 통일 |
| 단정 | 사실 서술만. 「〜でしょう」 추측 남발 금지 |
| 물음 | 본문에는 쓰지 않는다. **클로징에서만 1회** |
| 부호 | 문말은 **句点(。)** 통일. `！` `？` 사용 금지 |

### 7-2. 금지 어휘 — 브랜드 결정 사항

| 금지 | 사유 |
|---|---|
| **Cross-Border / クロスボーダー** | 폐기 확정. 博報堂·訪日コム가 선점, 越境EC 문맥으로 오염 |
| **「つなぐ」 남발** | 회사 카피 전반에서 과사용 지적됨. 1기사 1회까지 |
| **「一緒に」 남발** | 동상 |
| **「設計」 남발** | 소개서에 이미 10회 이상. **자기 규정(L2·本質)에만** 쓴다. 기사 본문에서는 1〜2회 |
| **「大幅」「劇的」** | 景表法 리스크 |

### 7-3. 문장

- **1문 60자 이내.** 넘으면 자른다
- **1단락 3문 이내**
- 접속사로 시작하는 단락 연발 금지 (「しかし」「一方で」)
- 체언 종결(体言止め) 금지. 기사가 광고 카피처럼 보인다

### 7-4. 좋은 문장의 조건

```
❌ 自然に囲まれた、ゆっくり癒やされる旅館でした。
✅ 福岡空港からレンタカーで約1時間20分。公共交通機関の場合は、
   最寄り駅から予約制の送迎を利用します。
```

**"판단할 수 있는가"** 가 유일한 기준이다. 형용사를 지우고 조건·숫자를 넣는다.

## 9. 클로징 — CONTACT 문법과 잇는다

본문 마지막은 **CONTACT 페이지와 같은 문법**으로 닫는다.

```
旅先の選択は、日本に到着してから始まるのではありません。
韓国で検索し、比較し、予約を検討する瞬間から始まっています。
```

| 규칙 | |
|---|---|
| 분량 | **2〜3행** |
| 구조 | 「○○ではありません。△△です。」 — 전제를 뒤집는다 |
| 금지 | 「お問い合わせください」 직접 유도. **CTA는 시스템이 붙인다** |
| 금지 | 자사 서비스 나열 |

기사 하단의 「この件で相談する」 버튼은 `?s=<postId>` 로 문의 폼을 자동 선택·프리필한다. **본문에서 영업하지 않아도 도선이 이미 있다.**

|---|---|
| **전각 `｜`** | 표가 안 만들어진다. **반각 `\|`** 만 인식 |
| 스마트 대시·따옴표 | 마크다운을 깨뜨린다. 일본어 IME 자동 변환 주의 |
| 이미지 안의 문자 | **검색·생성AI가 못 읽는다.** 숫자와 결론은 반드시 본문 또는 표에 |
| 이미지 용량 | 업로드 전 장변 1600px · WebP · 300KB 이하로 압축(squoosh.app) |

## 13. 형식이 안 맞는 주제는 어떻게 하나

이 규칙서는 **「판단 기준을 제시하는 해설 기사」** 형식이다. 전부를 이 틀에 넣을 수 없다.

| 주제 유형 | 형식 |
|---|---|
| 판단 기준 제시 | **본 규칙서 형식** (비교표 + 체크리스트) |
| 케이스 해설 | 課題 → 解決策 → 成果 → 本質 (소개서 문법) |
| 데이터 리포트 | 수치 중심. 단 출처 규율은 동일 |
| お知らせ | 500〜800자. 표·체크리스트 불필요 |

**억지로 표를 만들지 마라.** 표가 안 나오는 주제는 형식을 바꾼다.
